# Project Description

## 1. Project Overview

This project builds a data processing and analytics pipeline using the MovieLens 100K dataset with Python, Apache Spark, HDFS, and Cassandra. The main dataset files used in this project are:

- `u.user`: user information, including user ID, age, gender, occupation, and ZIP code.
- `u.data`: rating information, including user ID, movie ID, rating, and timestamp.
- `u.item`: movie information, including movie ID, movie title, release date, IMDb URL, and genre indicators.

The objective of this project is to read raw MovieLens data from HDFS into Spark, create RDDs, convert them into DataFrames, perform cleaning and analytical queries, and write the results into Cassandra tables. The final results are then verified in `cqlsh` by selecting records from the Cassandra tables.

The five analytical tasks completed in this project are:

1. Calculate the average rating for each movie.
2. Identify the top ten movies with the highest average ratings.
3. Identify users who rated at least 50 movies and determine their favourite movie genre.
4. Find all users who are less than 20 years old.
5. Find all users whose occupation is `scientist` and whose age is between 30 and 40 years old.

## 2. Environment Requirements

This project was executed in a virtual machine environment using HDFS, Apache Spark, Cassandra, and Python. Since the course environment uses an older Spark version, Cassandra connector compatibility is an important requirement.

The recommended environment is:

| Component | Description |
|---|---|
| Operating environment | Linux virtual machine |
| Data storage | HDFS |
| Distributed computing | Apache Spark 2.3.0 |
| Database | Apache Cassandra |
| Programming language | Python / PySpark |
| Remote access tool | PuTTY |
| Dataset | MovieLens 100K |

A key compatibility issue in this project is the Spark Cassandra Connector version. Since Spark 2.3.0 belongs to the Scala 2.11 ecosystem, newer connector versions may not work correctly. Therefore, the connector package was specified in the `spark-submit` command:

```bash
spark-submit --packages com.datastax.spark:spark-cassandra-connector_2.11:2.5.2 assignment2.py
```

At the same time, the following configuration was not repeated inside the Python code:

```python
.config("spark.jars.packages", "...")
```

In other words, this line was commented out or removed from `build_spark_session()` to avoid dependency conflicts or repeated connector configuration.

## 4. Code Section Explanation

### 4.1 Importing Libraries and Creating SparkSession

The code first imports the required PySpark modules, including `SparkSession`, SQL functions, schema data types, and window functions.

The function `build_spark_session()` is used to create a SparkSession and configure the Cassandra host:

```python
SparkSession.builder \
    .appName(APP_NAME) \
    .config("spark.cassandra.connection.host", CASSANDRA_HOST) \
    .getOrCreate()
```

In this project, `spark.jars.packages` was not configured inside the code. Instead, the Cassandra connector was specified in the `spark-submit` command. This approach is more stable for Spark 2.3.0 because it avoids connector version conflicts.

### 4.2 Parsing the Raw MovieLens Files

The code defines three parsing functions:

- `parse_user()`: parses `u.user`, which uses `|` as the delimiter.
- `parse_rating()`: parses `u.data`, which uses tab as the delimiter.
- `parse_movie()`: parses `u.item`, which uses `|` as the delimiter.

The `u.item` file is more complex because it contains basic movie information and 19 genre indicator columns, such as `Action`, `Comedy`, `Drama`, and `Sci-Fi`. Each genre column uses 0 or 1 to indicate whether the movie belongs to that genre.

### 4.3 Creating RDDs from HDFS

Spark reads the three raw files from HDFS using `sparkContext.textFile()`:

```python
users_rdd = sc.textFile(...).map(parse_user)
ratings_rdd = sc.textFile(...).map(parse_rating)
movies_rdd = sc.textFile(...).map(parse_movie)
```

This step satisfies the assignment requirement of creating RDD objects from the raw dataset. RDDs are Spark's low-level distributed data structure and are useful for showing the transformation from raw text files into structured data.

### 4.4 Converting RDDs into DataFrames

The code defines schemas for the three datasets and then converts each RDD into a Spark DataFrame using:

```python
spark.createDataFrame(rdd, schema)
```

The main DataFrames are:

- `users_df`
- `ratings_df`
- `movies_df`

The code also applies `dropna()` to remove rows with missing values in key fields. This step is part of basic data cleaning and preprocessing.

### 4.5 Converting Movie Genres from Wide Format to Long Format

In the MovieLens `u.item` file, genres are stored as 19 separate columns. To calculate each user's favourite genre, these genre columns need to be transformed from a wide format into a long format.

The transformed `movie_genres_df` has a structure similar to:

| movie_id | movie_title | genre |
|---|---|---|
| 1 | Toy Story (1995) | Animation |
| 1 | Toy Story (1995) | Children |
| 1 | Toy Story (1995) | Comedy |

This transformation allows one movie to be associated with multiple genres. The result can then be joined with the ratings data to count how frequently each user rated movies from each genre.

### 4.6 Task 1: Average Rating for Each Movie

For Task 1, `ratings_df` is joined with `movies_df` using `movie_id`. The data is then grouped by movie:

```sql
GROUP BY movie_id, movie_title
```

The query calculates:

- `average_rating`: the average rating of the movie;
- `rating_count`: the number of ratings received by the movie.

The result is written into the Cassandra table `movie_average_ratings`.

### 4.7 Task 2: Top Ten Movies with the Highest Average Ratings

Task 2 calculates the average rating for each movie and sorts the results using:

```sql
ORDER BY average_rating DESC, rating_count DESC, movie_title ASC
LIMIT 10
```

This returns the top ten movies with the highest average ratings. The result is written into the Cassandra table `top_ten_movies`.

### 4.8 Task 3: Favourite Genre for Users Who Rated at Least 50 Movies

Task 3 first counts how many movies each user has rated and filters users using:

```python
rated_movie_count >= 50
```

Then, the ratings DataFrame is joined with the long-format movie genre DataFrame. The code counts how many times each user rated movies from each genre. Finally, the window function `row_number()` is used to select the genre with the highest count for each user. This genre is treated as the user's `favourite_genre`.

The result is written into the Cassandra table `favourite_genres`.

In this project, "favourite genre" is defined based on rating frequency, not based on the average rating given to each genre. For example, if a user most frequently rated Drama movies, then Drama is considered that user's favourite genre.

### 4.9 Task 4: Users Less Than 20 Years Old

Task 4 filters the users table using:

```sql
WHERE age < 20
```

The result is written into the Cassandra table `users_under_20`.

### 4.10 Task 5: Scientists Aged Between 30 and 40

Task 5 filters users whose occupation is `scientist` and whose age is between 30 and 40:

```sql
WHERE occupation = 'scientist'
  AND age BETWEEN 30 AND 40
```

The result is written into the Cassandra table `scientists_30_to_40`.

### 4.11 Writing to Cassandra and Validating Results

After the five analytical result DataFrames are generated, the code writes them into Cassandra using the Spark Cassandra Connector:

```python
df.write \
  .format("org.apache.spark.sql.cassandra") \
  .mode("append") \
  .options(table=table_name, keyspace=CASSANDRA_KEYSPACE) \
  .save()
```

After the Spark job finishes, the five Cassandra tables are queried in `cqlsh` to verify that the data has been stored successfully.

## 7. Project Challenges

The main challenge in this project was the version compatibility between Apache Spark and the Spark Cassandra Connector.

Because the experimental environment uses Spark 2.3.0, newer versions of the Spark Cassandra Connector may not be compatible. Newer connectors may depend on different Scala or Spark versions, which can lead to package downloading errors, class loading errors, or connector initialization failures.

The solution was to specify a compatible connector version in the `spark-submit` command:

```bash
spark-submit --packages com.datastax.spark:spark-cassandra-connector_2.11:2.5.2 assignment2.py
```

At the same time, the following line in `build_spark_session()` was commented out or removed:

```python
.config("spark.jars.packages", ...)
```

This prevents duplicate dependency configuration and allows Spark to load the Cassandra connector consistently during job submission.

Another challenge was the structure of the `u.item` file. The movie genres are stored as 19 separate columns, which is not convenient for calculating users' favourite genres. To solve this problem, the genre columns were transformed into a long-format table before joining with the ratings data.

In addition, Cassandra query results are not always displayed in the same order as Spark output. Therefore, using `LIMIT 10` in `cqlsh` mainly verifies that the data exists and the table fields are correct. For ranking-based analysis, the sorted Spark output is more suitable for final interpretation.
